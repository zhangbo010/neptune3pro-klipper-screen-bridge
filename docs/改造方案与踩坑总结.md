# 海王星 3 Pro 无损改 Klipper + J17/J33 串口桥接 + 屏幕热插拔与 WiFi 面板改造方案与踩坑总结

> **机型**：Elegoo Neptune 3 Pro（海王星 3 Pro）
> **主板**：`ZNP Robin Nano_DW V2.2`（主控 `STM32F401RCT6`，晶振 `8 MHz`）
> **上位机**：`MKS Pi V1.1`（Armbian，UART0 = `/dev/ttyS0`）
> **屏幕**：原厂陶晶驰串口屏 `TJC4827X243_011`（4P4C 电话线接口 `J33`）
> **完成日期**：2026-11-11

---

## 1. 主机通讯链路：主板 J17 (`USART2 PA3/PA2`) ↔ MKS Pi `UART0` (`/dev/ttyS0`)

- **设计目标**：不占用外置 USB 口、不插外露 USB 线，直接通过机箱内部排线连接主板与 MKS Pi。
- **硬件实现**：
  - 复用主板上的 **J17（8Pin ESP8266 WiFi 模块母座）**，对应 `STM32F401RCT6` 的硬件 **`USART2`（`PA3` = RXD2, `PA2` = TXD2）**。
  - 连接到 MKS Pi 40Pin GPIO 上的 **`UART0`（`/dev/ttyS0`）**：
    - `J17 Pin 2 (GND)` ↔ `MKS Pi GND`
    - `J17 Pin 3 (PA2 / TXD2)` ↔ `MKS Pi UART0_RX`
    - `J17 Pin 4 (PA3 / RXD2)` ↔ `MKS Pi UART0_TX`
  - **关键参数**：Katapult 与 Klipper 统一使用 **`250000` 波特率**（与 MKS Pi `/dev/ttyS0` 16550A 分频完全对齐，实测 0 重传、0 丢包）。

---

## 2. 屏幕桥接链路：修正 J33 电话线屏口真实引脚为 `USART6 PA12(RX)/PA11(TX)`

- **核心踩坑与根因定位**：
  - 早期经验误以为 `STM32F401` 的 `USART6` 默认在 `PC7(RX)/PC6(TX)`，结果配置后与 `printer.cfg` 中的 **`stepper_z` (`step_pin: PC7`)** 和 **`extruder` (`enable_pin: !PC6`)** 发生严重引脚冲突，且屏幕完全无响应。
  - 经核对 `ZNP_Robin_Nano_DW_V2.2_SCH.pdf` 官方原理图第 2 页（MCU 页）与第 10 页（`P-AUX.SchDoc` 的 `J33` 电话线座）：
    - 主板上 `PC7` 确实是 `Z_STEP`，`PC6` 确实是 `E0_EN`；
    - **`J33`（H43 屏幕电话线接口）的 `TXD6 / RXD6` 实际接在 `STM32F401RCT6` 的第 44/45 脚 `PA11(TXD6) / PA12(RXD6)`（`USART6` 的 Alternate Function 8）**！
- **固件与上位机桥接实现**：
  - **MCU 侧 (`src/klipper_bridge/screen_bridge.c`)**：
    - 声明 `DECL_CONSTANT_STR("RESERVE_PINS_screen_bridge", "PA12,PA11");`
    - 将 `PA12(RX)` / `PA11(TX)` 配置为 `AF8 (USART6)`，波特率 `115200`。
    - 采用独立环形缓冲区（`RX_SIZE=2048`, `TX_SIZE=4096`），中断优先级设为 `3`（低于主机串口 `0` 和步进定时器 `2`），**绝不抢占实时步进脉冲**，任何溢出/帧错误仅计数丢弃、绝不触发 MCU `shutdown()`。
    - 考虑到 Klipper 单帧上限 `MESSAGE_MAX = 64` 字节，每次 `bridge_tx` / `bridge_rx` 负载严格限制为 `48` 字节。
  - **上位机侧 (`src/klipper_bridge/screen_bridge.py`)**：
    - 在 Klipper 启动时创建虚拟串口软链接 `/tmp/ttyTJC`（`chmod 0666`），以 `10ms` 周期轮询 MCU `bridge_rx`，供 `KlipperLCD` 无感透明读写。

## 3. ST-Link 无硬复位线下的复位窗口抢占烧录与 Katapult 在线升级

- **踩坑现象**：
  - 主板 J1 SWD 接口仅接了 4 根线（`3.3V / GND / SWDIO / SWCLK`，未接 `NRST` 硬复位线）。
  - 先前刷入的旧固件因晶振/时钟配置不匹配，上电几毫秒内即执行 `WFI` 关闭时钟或跑飞，导致 `pyOCD` / `ST-Link` 常规连接直接报 `TransferError (0x06)`，无法擦写 Flash。
- **抢占烧录解决方案**：
  1. 编写底层 `STLink` USB 抢占脚本：在循环中以微秒级间隔向 `AIRCR (0xE000ED0C)` 写入 `0x05FA0004 (SYSRESETREQ)` 触发软复位，同时立即向 `DHCSR (0xE000EDF0)` 写入 `0xA05F0003 (C_DEBUGEN | C_HALT)` 并在 `DEMCR (0xE000EDFC)` 开启 `VC_CORERESET (0x01000001)`，成功在复位向量入口 `0x080002ac` 处将内核死死摁住（Halt）。
  2. 立即向 **`DBGMCU_CR (0xE0042004)` 写入 `0x00000007`**，强制开启 Sleep/Stop/Standby 调试时钟，彻底防止后续因 `WFI` 断连。
  3. 直接操作 `STM32F4` Flash 寄存器（`0x40023C00`）擦除 Sector 0~3，并按双段结构写入并完成 100% 逐字节校验：
     - **`0x08000000`**：`katapult_F401_USART2_J17.bin`（`16KiB` 引导区，`USART2 PA3/PA2`，`250000` 波特率）
     - **`0x08004000`**：`klipper_F401_USART2_J17_bridge.bin`（`16KiB` 偏移应用区）
- **后续免拆机在线升级指令**：
  只要 `Katapult` 在位，以后在 MKS Pi 上随时可通过 `/dev/ttyS0` 一键在线刷写新固件：
  ```bash
  sudo systemctl stop klipper
  python3 ~/katapult/scripts/flashtool.py -d /dev/ttyS0 -b 250000 -r && sleep 0.5 && python3 ~/katapult/scripts/flashtool.py -d /dev/ttyS0 -b 250000 -f ~/klipper/out/klipper.bin
  sudo systemctl start klipper
  ```

## 4. 风扇引脚修正与联动配置（`FAN1=PB0`、`FAN2=PA7`、`PB2` 占位）

- **原理图核实**：
  - `FAN1`（主板电器仓散热风扇接口）：控制脚为 **`PB0`**。
  - `FAN2`（喷头喉管散热风扇接口）：控制脚为 **`PA7`**。
- **最终配置策略（`src/config/printer.cfg`）**：
  - 将电器仓风扇（`PB0`）与喉管散热风扇（`PA7`）均配置为 `[heater_fan]`，绑定 `heater: extruder`、`heater_temp: 50.0`、`fan_speed: 1.0`——**当喷头加热超过 50°C 时两路风扇同步自动满速开启，低于 50°C 自动关闭静音**。
  - 由于 `KlipperLCD` 服务启动时强依赖读取 Klipper 的 `[fan]` 对象，使用主板上未引出的空闲引脚 **`PB2`** 建立占位 `[fan]`，保证屏幕服务正常初始化且可正常显示全套 UI。

## 5. 屏幕电话线热插拔自动重连机制（PTY 保活 + `0x00/0x1A/0x88` 捕获 + 4s 主动心跳）

- **问题根因**：
  1. 当拔掉屏幕电话线再插回时，屏幕重新上电并停留在 `boot` 开机画面（等待上位机发送 `com_star` 和 `page main`）。
  2. 待机状态下如果喷头/热床温度恒定不变，原版 `KlipperLCD` 不会向屏幕发送任何数据，导致双方死锁在 `boot` 页。
  3. 即使温度波动触发了 `main.nozzletemp.txt=...` 发送，由于屏幕当前在 `boot` 页而非 `main` 页，陶晶驰屏幕会回传错误码 **`0x1A 0xFF 0xFF 0xFF`（变量名称无效）**，而原版 `lcd.py` 将 `0x1A` 当作未知乱码直接丢弃。
- **三重修复方案**：
  1. **PTY 持久保活（`screen_bridge.py`）**：Klipper 在 `disconnect/shutdown` 时不再销毁 `/tmp/ttyTJC` PTY，避免 `KlipperLCD` 因句柄失效断连；同时 `lcd.py` 增加文件 `(st_dev, st_ino)` 监控，即使 Klipper 服务完全重启重建了 PTY 也能自动重开串口。
  2. **4 秒主动温度心跳（`main.py`）**：在 `periodic_update` 循环中每 2 个周期（约 4 秒）强制向屏幕发送一次 `main.nozzletemp.txt` 与 `main.bedtemp.txt`。如果屏幕刚被拔插并卡在 `boot` 页，这笔心跳会立即激发出屏幕的 `0x1A` 响应。
  3. **捕获 `0x00 / 0x1A / 0x88` 及 `0x2202 (0x0F)` 立即全量重初始化（`lcd.py` + `main.py`）**：一旦收到屏幕上电脉冲 `0x00`、就绪码 `0x88`、或 `boot` 页变量错误码 `0x1A`，`on_screen_reconnected()` 在 `0.2s` 内自动下发空指令清缓冲、`com_star`、`main.va0.val=1`、机器尺寸、WiFi/IP 信息、跳转 `page main` 并立即刷新温度，实现**拔插电话线 1~2 秒内无感恢复主界面**。

## 6. 免刷屏幕 TF 卡的触控 WiFi 扫描与密码输入面板（改造 `Console` + `Macro` 页）

- **设计巧思**：
  - 在不拆屏重刷 `.tft` 固件的前提下，直接利用现有屏幕固件自带的 **`Console`（含多行文本框 `console.slt0`、单行输入框 `console.t0`、全键盘）** 与 **`Macro`（含下拉选择框 `macro.cb0` 与 Send 按钮）**，将其彻底改造为直观的 **WiFi 管理面板**。
- **核心功能与防坑细节（`src/KlipperLCD/main.py`）**：
  1. **原子级整屏刷新（零闪烁）**：废弃原版逐行累加 `console.slt0.txt` 的慢速写法，改为单次拼接整屏字符串写入 `console.buf.txt` 后原子赋值给 `console.slt0.txt`，瞬间刷新且绝不卡死串口。
  2. **过滤非 ASCII 乱码 SSID**：由于屏幕内部英文字库不支持中文 UTF-8，扫描时自动过滤含中文的 SSID，确保下拉框与列表 100% 清晰无乱码。
  3. **丝滑两步连网流程**：
     - 点屏幕顶部 **Macro** → 下拉框直接列出 `[RESCAN_WIFI]` 及信号最强的 WiFi 列表 → 选中目标 WiFi 点 **Send** → **自动跳回 Console 页面并清空输入框**；
     - 点底部输入框弹出屏幕全键盘 → **直接输入纯密码** 点 Send → 后台异步调用 `sudo -n nmcli` 连接（已配置 `/etc/sudoers.d/klipper-nmcli` 免密）。
  4. **密码错误防失联保护**：连接前先清理同名旧配置防止旧错密码残留；若新密码错误导致连接失败且无线断开，自动调用 `nmcli connection up <原WiFi>` 恢复之前的可用网络连接，并在屏幕顶部状态栏与 `About Machine` 页面实时更新当前 `IP (SSID)`。
